# コンポーネント: PlantUML事前レンダリング埋め込み（plantuml-embed）

## 適用条件

シーケンス図・クラス図・C4図など、`flow-steps`（縦積みステップ）や手描きインラインSVGでは表現しづらい構造化された図が必要な場合のみ使う。単純な処理フローは`flow-steps`で足りるので、そちらを優先する。

## 大原則：実行時の外部依存を作らない

既存Skillのオフライン閲覧原則（Mermaid CDN禁止）と同じ理由で、PlantUMLも**HTMLの実行時にレンダリングサーバへアクセスする方式は使わない**。必ず**執筆時（生成時）にローカルでレンダリングし、結果のSVGをHTMLへ埋め込む**。生成後のHTMLは外部ネットワークに一切依存しない状態にする。

## 手順

1. **ソースの確認**：ローカルにPlantUMLレンダラーが無い場合（`command -v plantuml`や`java -jar plantuml.jar`が使えない場合）、実行環境に用意されているか人間に確認する。無ければ「執筆時のみ・生成物には影響しない一時利用」であることを明記した上で導入可否を確認する（新規依存の追加は人間の判断が要る、プロジェクトルール）
2. **図のソースを版管理する**：`.puml`ファイルを、対応するMD原稿と同じ場所（`docs/deliverables/<成果物名>/diagrams/*.puml`等）に保存する。SVGはこの`.puml`から再生成できる派生物として扱う
3. **レンダラー・テーマ・フォントを固定する**：使用したPlantUMLのバージョン、テーマ（`!theme`指定があれば）、フォント指定を`.puml`ファイル冒頭のコメントか同ディレクトリのREADMEに記録する。レンダラーのバージョン差で図が無断に変化するのを防ぐ
4. **SVGとして出力する**（`-tsvg`オプション相当）。PDF/印刷互換性が必要な場合のみ、同じ`.puml`ソースからPNGも生成し、どちらを正規の埋め込み対象にするか決める（両方埋め込むと二重管理になるため避ける）
5. **SVGをサニタイズする**：生成されたSVGに以下が含まれていないか確認し、含まれていれば除去する
   - `<script>`要素
   - 外部への`href`/`xlink:href`（`http(s)://`を指す参照）
   - `<foreignObject>`
   - リモートフォント参照（`@font-face`のurl(http...)）
6. **アクセシビリティ**：SVGに`<title>`と`<desc>`（または直後にキャプション`<p class="caption">`）を付け、図の内容をテキストでも把握できるようにする
7. **HTMLへの埋め込み**：`.diagram`コンポーネント内にSVGをそのままインライン展開する（`<img>`ではなくSVG要素を直接埋め込むと拡大縮小がきれいになる）

```html
<div class="diagram">
  <svg ...>
    <title>[図のタイトル]</title>
    <desc>[図が示す内容の要約]</desc>
    ...
  </svg>
  <p class="caption">[図番号・キャプション]</p>
</div>
```

## 再現性の確認

生成後、`.puml`ソースを同じレンダラー・バージョンで再実行してSVGが一致するか（差分が意図しない変化を含まないか）を確認する。CIが無い前提のため、この確認は手動でよい。
