# コンポーネント: 複数ファイル分割＋相互リンク（multifile-packaging）

## 適用条件

1ファイルのHTMLが長大になり閲覧性が落ちる場合のみ使う。目安：章数が多い（arc42ベースの基本設計書等）、または原稿が数十問規模のQ&A。小〜中規模の文書は単一HTMLのままにする（分割をデフォルトにしない）。

## 配布単位

**1ディレクトリで自己完結**させる。ZIPで送る場合も同様に1階層にまとめる。index.htmlだけを送る／リンク先の一部ファイルが欠落する事故を防ぐため、生成後に全ファイルが同梱されているか確認する。

```
docs/deliverables/<成果物名>/
  index.html          # 全体目次。各章へのリンクのみ、本文は持たない
  01-<章名>.html
  02-<章名>.html
  ...
  <成果物名>.md         # 原稿(全章分、単一ファイルでよい)
```

## ナビゲーション規約

- 各章ファイルの先頭・末尾に共通ナビゲーション（前の章／目次に戻る／次の章）を置く。静的HTMLでサーバサイドインクルードは使えないため、**生成時に同じナビゲーションHTMLを全ファイルへ複製する**（手作業でズレないよう、コピー元を1箇所決めておく）
- リンクは相対パスの`<a href="02-xxx.html#anchor">`形式。絶対パス・`file://`を含む絶対URLは使わない
- ファイル名は安定させる（一度決めた章ファイル名を、章の並び替え以外の理由で変えない）。要件定義書↔基本設計書のようにファイル間トレーサビリティを張る場合、リンク切れの元になるため特に注意する
- 各章ファイルは他ファイルと独立して開いても文脈を失わないよう、章タイトルの下に「本資料は『<成果物名>』の一部です（[目次に戻る](index.html)）」の1行を入れる

## 生成後チェック

- 全リンク（`<a href="...">`）のリンク先ファイルが実在するか確認する（リンクチェック）
- 共有アセット（画像・フォント等がある場合）が各ファイルから参照可能な場所に配置されているか確認する
- `docs/deliverables/<成果物名>/`配下の全ファイルが`git add`対象になっているか確認する
