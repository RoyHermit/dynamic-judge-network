Dynamic Judge Networks

A decision-making network inspired by the brain's dual-process theory (reflex and deliberation) and the gating mechanism of the basal ganglia. Depending on input difficulty and urgency, a “judge circuit (Judge)” dynamically arbitrates the inference path at millisecond timescales, delivering Speed (Fast), Compute Sparsity (Sparse), and Environmental Adaptability (Adaptive) simultaneously.

Why Do We Need a “Dynamic Judge”?

Structural limitations of conventional deep learning, and a breakthrough drawn from biology

✕

Conventional Fixed Networks (Static Dense Models)

  • • Uniform compute cost: Whether the input is as trivial as “1+1” or an extremely hard problem, every parameter is used (100% FLOPs).
  • • Fixed latency: Even where real-time decisions are required (edge devices, autonomous driving, emergency avoidance), inference latency cannot be shortened to fit the situation.
  • • Confidence-blind: The model does not assess whether it is uncertain or confident, and always runs wastefully to a fixed depth.
✓

Dynamic Judge Network

  • • Bio-inspired gated arbitration: Like the basal ganglia, a lightweight judge circuit (Judge) sits right after the “initial sensory layer.” Easy inputs are answered immediately via the Fast Path (early exit).
  • • Dynamic Sparsity: Additional deep expert layers and recursive reasoning modules (Deep Path) are selectively activated only for hard or ambiguous inputs.
  • • Adaptation to environmental constraints: The decision threshold $\theta$ is adjusted automatically in real time according to remaining battery, deadline (latency budget), and input noise level.

1. Fast (Speed, Ultra-Low Latency)

Standard data, which makes up roughly 60–80% of inputs, is resolved in the early lightweight layers (High Confidence). Average inference time is cut by up to 70%, enabling immediate-response tasks such as emergency braking.

2. Sparse (Dynamic Sparsity)

Only the neurons/modules that are needed are fired on demand. Unlike static sparsity, which prunes weights permanently, the activation topology changes dynamically per input to save power.

3. Adaptive (Dynamic Adaptability)

The Judge self-optimizes in real time the trade-off between input uncertainty and external costs (power consumption, time limits), gaining robustness that does not break down even in extreme environments.

Mathematical Formulation

Mathematical Model of Judge Decisions

Formulation of the confidence estimate and dynamic cost function that shape the decision boundary

1. Quantifying Prediction Confidence ($C$)

Given the initial features $h^{(1)}$, the Judge computes confidence from the output probability distribution $P = \text{Softmax}(W_j h^{(1)})$ using either entropy or the margin between the top two classes:

C(x) = p_{(1)} - p_{(2)} \quad \text{or} \quad C(x) = 1 - \frac{H(P)}{\log K}

Note: $p_{(1)}, p_{(2)}$ are the probabilities of the two highest-probability classes. $H(P)$ is the Shannon entropy.

2. Environment-Linked Dynamic Threshold ($\theta_{dynamic}$)

The threshold $\theta$ is not fixed; it slides adaptively according to the external urgency $U \in [0, 1]$ and the compute-cost sensitivity $E \in [0, 1]$:

\theta(t) = \text{clip}\Big( \theta_0 - \alpha \cdot U(t) - \beta \cdot E(t), \; \theta_{min}, \; \theta_{max} \Big)

Under urgency ($U \uparrow$) or power saving ($E \uparrow$), the threshold drops and even modest confidence is accepted for an immediate answer (Fast Path).

3. Joint Objective (Combined Loss Function)

Training is end-to-end: a penalty $\mathcal{L}_{cost}$ for wasted computation is added to the task-accuracy loss $\mathcal{L}_{task}$:

\mathcal{L} = \mathcal{L}_{task}(y, \hat{y}) + \lambda_1 \cdot \mathbb{I}(\text{Deep}) \cdot \text{FLOPs}_{deep} + \lambda_2 \cdot \mathcal{L}_{judge}

# Bio-inspired Dynamic Judge Network Core Implementation
import torch
import torch.nn as nn
import torch.nn.functional as F

class DynamicJudgeBlock(nn.Module):
    """
    Estimates confidence from the input features and
    dynamically arbitrates between an early exit (Fast Exit) and deep computation (Deep Path).
    """
    def __init__(self, feat_dim, num_classes, base_threshold=0.75):
        super().__init__()
        self.fast_classifier = nn.Linear(feat_dim, num_classes)
        self.confidence_head = nn.Sequential(
            nn.Linear(feat_dim, 64),
            nn.ReLU(),
            nn.Linear(64, 1),
            nn.Sigmoid()
        )
        self.base_threshold = base_threshold

    def compute_adaptive_threshold(self, urgency=0.0, energy_bias=0.0):
        # Mimics biological emergency response: relax the criterion under urgency
        theta = self.base_threshold - (0.35 * urgency) - (0.25 * energy_bias)
        return torch.clamp(torch.tensor(theta), min=0.20, max=0.95)

    def forward(self, x, urgency=0.0, energy_bias=0.0):
        logits_fast = self.fast_classifier(x)
        confidence = self.confidence_head(x).squeeze(-1) # [Batch]
        
        dynamic_threshold = self.compute_adaptive_threshold(urgency, energy_bias)
        should_fast_exit = confidence >= dynamic_threshold
        
        return logits_fast, confidence, should_fast_exit


class DynamicJudgeNetwork(nn.Module):
    def __init__(self, in_features, hidden_dim, num_classes):
        super().__init__()
        # Stage 1: Lightweight sensory feature extraction (Fast Sensory)
        self.stage1 = nn.Sequential(
            nn.Linear(in_features, hidden_dim),
            nn.BatchNorm1d(hidden_dim),
            nn.GELU()
        )
        # Judge Unit: dynamic decision unit
        self.judge = DynamicJudgeBlock(hidden_dim, num_classes)
        
        # Stage 2: Deep reasoning module (Deep Experts / Deliberative Network)
        self.stage2 = nn.Sequential(
            nn.Linear(hidden_dim, hidden_dim * 4),
            nn.GELU(),
            nn.Linear(hidden_dim * 4, hidden_dim),
            nn.GELU(),
            nn.Linear(hidden_dim, num_classes)
        )

    def forward(self, x, urgency=0.0, energy_bias=0.0):
        # 1. Extract shared initial features
        h1 = self.stage1(x)
        
        # 2. Dynamic routing decision by the Judge
        logits_fast, confidence, should_fast_exit = self.judge(h1, urgency, energy_bias)
        
        # 3. If the Fast Exit condition is met, skip Stage 2 entirely (0 FLOPs)
        if should_fast_exit.all():
            return logits_fast, {"path": "fast_only", "savings": 0.78}
        
        # Activate Stage 2 only for hard samples
        logits_deep = self.stage2(h1)
        
        # Merge final outputs (confidence-weighted or switched)
        final_output = torch.where(should_fast_exit.unsqueeze(-1), logits_fast, logits_deep)
        return final_output, {"path": "hybrid_or_deep", "savings": 0.15}
